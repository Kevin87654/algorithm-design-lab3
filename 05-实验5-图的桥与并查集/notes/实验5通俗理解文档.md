# 一、这次实验到底要干什么

这次实验的主题是：在一个无向图中找出所有的“桥”。

所谓无向图，可以理解成一堆点和线：

- 点表示顶点。
- 线表示边。
- 无向图中的边没有方向，也就是说 A 连到 B 和 B 连到 A 是同一回事。

“桥”是一种特殊的边。

如果把某一条边删掉之后，原本连在一起的图被分成了更多块，那么这条边就是桥。

换一种更好理解的话说：

如果一条边是某两个部分之间唯一的连接通道，那么它就是桥。一旦删掉它，两边就断开了。

例如：

```text
A -- B -- C
```

这里边 A-B 和 B-C 都是桥。删掉 A-B 后，A 就和 B、C 断开了。删掉 B-C 后，C 也会断开。

再看一个有环的例子：

```text
A -- B
|    |
D -- C
```

这个图是一个环。删掉任意一条边，剩下的点之间仍然可以绕另一条路连通，所以这些边都不是桥。

所以可以记住一句话：

**桥一定不在环上；在环上的边一定不是桥。**

# 二、PPT 中和本实验有关的知识点

老师给的《第七章 图论算法》PPT 内容很多，但和本实验最相关的主要是下面几部分。

## 1. 图的基本概念

PPT 前面讲了图的基本组成：

- 图由顶点 V 和边 E 组成。
- 无向图中的边没有方向。
- 路径是从一个点走到另一个点经过的一串顶点和边。
- 环是起点和终点相同的一条路径。

这些概念是理解“桥”的基础。

桥和环的关系非常重要：

- 如果一条边在环上，删掉它之后还可以绕环上的其他边走过去，所以它不是桥。
- 如果一条边不在任何环上，它就可能是两部分之间唯一的连接，因此它是桥。

## 2. 连通性和连通分支

PPT 中讲了连通图和连通分支。

如果无向图中任意两个顶点之间都有路径相连，那么这个图就是连通图。

如果图不是完全连通的，它会被分成几个互相不连通的部分，每个部分就是一个连通分支。

本实验中桥的定义就和连通分支直接相关：

**删除一条边后，如果连通分支数量增加，这条边就是桥。**

这也是基准算法的核心思想。

## 3. 邻接表

PPT 里讲了图的两种常见存储方式：

- 邻接矩阵
- 邻接表

本实验代码使用的是邻接表。

邻接表可以理解成：

每个点后面挂一个列表，列表里保存和它直接相连的点。

例如：

```text
0: 1, 2
1: 0, 3
2: 0
3: 1
```

这表示：

- 0 和 1、2 相连。
- 1 和 0、3 相连。
- 2 和 0 相连。
- 3 和 1 相连。

邻接表适合本实验，因为老师给的大图边很多，但远没有达到完全图的程度。使用邻接表可以节省空间，并且遍历某个顶点的邻居很方便。

## 4. DFS 深度优先搜索

PPT 中讲了 DFS，也就是深度优先搜索。

DFS 的思想可以理解成：

从一个点出发，能往前走就一直往前走，走不动了再退回来换路。

DFS 在本实验中有两个作用：

1. 在基准算法中，用 DFS 计算删除某条边后的连通分支数量。
2. 在高效算法中，用 DFS 建立 DFS 树，区分树边和非树边。

PPT 中还提到，如果使用邻接表，DFS 的时间复杂度是 O(V+E)。这里 V 表示顶点数，E 表示边数。

## 5. DFS 树边和非树边

PPT 中讲了 DFS 的边分类。

在无向图里，DFS 遍历时的边主要可以理解成两类：

- 树边：DFS 第一次访问一个新顶点时经过的边。
- 非树边：连接到已经访问过的顶点的边。

在本实验的高效算法里：

- 树边一开始都可能是桥。
- 非树边会形成环。
- 只要一条树边被某个环包含，它就不是桥。

这就是高效算法的关键思想。

## 6. 并查集

PPT 后面讲 Kruskal 算法时介绍了并查集。

并查集可以用来维护“不相交集合”，常用操作有：

- Make-Set：创建一个集合。
- Find：查找某个元素属于哪个集合。
- Union：合并两个集合。

在这次实验中，并查集不是用来求最小生成树，而是用来压缩已经处理过的 DFS 树路径。

简单理解就是：

如果一段路径已经被证明在环上，后面再遇到相关路径时，就不用重复一条边一条边检查了，可以通过并查集快速跳过已经处理过的部分。

# 三、基准算法怎么理解

基准算法就是最直接、最容易想到的算法。

桥的定义是：

删除一条边后，连通分支数量增加。

所以基准算法就直接按照定义做：

1. 先计算原图有多少个连通分支。
2. 枚举每一条边。
3. 临时忽略这条边。
4. 再计算图有多少个连通分支。
5. 如果连通分支数量变多了，说明这条边是桥。

伪代码如下：

```text
输入：无向图 G
输出：所有桥边 bridges

bridges = 空集合
baseComponents = 计算原图 G 的连通分支数量

对于图中的每一条边 e：
    临时忽略边 e
    currentComponents = 使用 DFS 计算当前图的连通分支数量

    如果 currentComponents > baseComponents：
        把 e 加入 bridges

返回 bridges
```

这个算法的优点：

- 思路非常直观。
- 和桥的定义完全一致。
- 适合验证小图的正确性。

这个算法的缺点：

- 太慢。
- 每一条边都要重新 DFS 一遍。
- 如果边很多，运行时间会非常长。

复杂度：

一次 DFS 是 O(V+E)。

有 E 条边，每条边都要 DFS 一次。

所以总时间复杂度是 O(E*(V+E))。

这就是为什么 largeG.txt 不适合跑基准算法。largeG.txt 有 1000000 个顶点和 7586063 条边，如果每条边都重新遍历整张图，计算量会非常夸张。

# 四、高效算法怎么理解

高效算法的核心思想是：

**先用 DFS 建一棵树，再用非树边找环。只要树边在环上，它就不是桥。**

可以分成几个步骤理解。

## 1. 第一步：DFS 建树

从某个顶点开始 DFS。

DFS 第一次访问新顶点时走过的边，就是树边。

例如：

```text
0 -- 1 -- 2
     |
     3
```

如果 DFS 从 0 开始，可能得到一棵 DFS 树。

树边暂时都被认为“可能是桥”。

## 2. 第二步：找到非树边

如果 DFS 遇到一条边，它连接的是已经访问过的点，而且不是父子之间的那条树边，那么它就是非树边。

非树边的意义很大。

因为非树边会把 DFS 树上的两个点重新连起来，从而形成一个环。

只要形成了环，这个环上的树边就都不是桥。

## 3. 第三步：用并查集压缩路径

对于每条非树边 (u, v)，它会让 u 和 v 在 DFS 树上的路径形成一个环。

于是我们从 u 和 v 往上走，直到它们相遇。

在往上走的过程中，经过的树边都在环上，所以都标记为非桥。

但是如果每次都从头往上走，还是可能重复处理很多路径。

所以代码用了并查集。

并查集的作用可以理解成：

把已经处理过的点直接“挂”到更上面的祖先处。以后再经过这里时，就可以直接跳过，不用重复走。

## 4. 高效算法伪代码

```text
输入：无向图 G
输出：所有桥边 bridges

对图 G 进行 DFS，生成 DFS 森林
把所有 DFS 树边先标记为桥
收集所有非树边
初始化并查集，每个顶点单独成集

对于每一条非树边 (u, v)：
    u = Find(u)
    v = Find(v)

    当 u 和 v 不在同一个集合时：
        如果 depth[u] < depth[v]：
            交换 u 和 v

        将 u 到父节点的树边标记为非桥
        将 u 所在集合合并到 parent[u] 所在集合
        u = Find(u)

遍历所有边
仍然标记为桥的边就是最终桥边

返回 bridges
```

高效算法的优点：

- 不需要对每条边重新遍历整张图。
- 能处理很大的图。
- 满足老师要求：必须使用并查集。

复杂度：

DFS 遍历整张图是 O(V+E)。

并查集操作的平均开销很小。

所以整体运行时间接近 O(V+E)。

# 六、mediumG.txt 和 largeG.txt 的结果怎么理解

程序运行结果如下。

mediumG.txt：

```text
Vertices: 250, Edges: 1273
Baseline bridge count: 0, time: 2 ms
DSU bridge count: 0, time: 0 ms
Baseline and DSU results match: YES
```

这说明：

- mediumG.txt 有 250 个顶点，1273 条边。
- 两种算法都认为桥数量是 0。
- 两种算法结果一致。
- 这个图中没有桥。

largeG.txt：

```text
Vertices: 1000000, Edges: 7586063
DSU bridge count: 8, time: 588 ms
```

这说明：

- largeG.txt 有 1000000 个顶点，7586063 条边。
- 高效算法找到了 8 条桥。
- 算法本身运行时间约 588 ms。
- 文件读取时间比较长，是因为 largeG.txt 文件很大。

为什么 largeG.txt 没有跑基准算法？

因为基准算法复杂度是 O(E*(V+E))。

largeG.txt 的 E 和 V 都非常大。如果对 7586063 条边逐条删除并重新 DFS，会非常慢，不适合实际运行。

所以程序默认跳过 largeG.txt 的基准算法，只运行高效算法。

# 七、代码整体结构怎么看

源代码主要可以分成这几部分。

## 1. 图结构

```text
Edge：保存边的两个端点
AdjEdge：保存邻接点和边编号
Graph：保存顶点数、边集合和邻接表
```

这样设计的原因是：

每条边都有编号，方便在算法中标记“忽略哪条边”或者“哪条边是桥”。

## 2. 读入数据

老师给的数据文件格式是：

```text
第一行：顶点数
第二行：边数
后面每一行：一条边的两个端点
```

代码会读取 `mediumG.txt` 和 `largeG.txt`，并建立邻接表。

## 3. 图 2 测试

代码中有一个函数专门手动构造图 2。

这样做是为了满足实验要求中的“用图 2 的例子验证算法正确性”。

## 4. 基准算法

对应函数是：

```text
baselineBridges
```

它会逐条忽略边，并重新计算连通分支数量。

## 5. 高效算法

对应函数是：

```text
dsuBridges
```

它会：

1. DFS 生成树。
2. 标记树边。
3. 收集非树边。
4. 用并查集处理环。
5. 输出最终桥边。

## 6. 主函数

主函数会依次执行：

1. 图 2 正确性验证。
2. mediumG.txt 测试。
3. largeG.txt 测试。

# 八、容易混淆的问题

## 1. 桥是不是“权值最小的边”？

不是。

桥和边的权值没有关系。

桥只和连通性有关。

如果删掉一条边后图被分成更多块，这条边就是桥。

## 2. 并查集是不是只能用于 Kruskal 算法？

不是。

PPT 里是在 Kruskal 算法中讲并查集，但并查集本质上是维护集合合并和查询的数据结构。

只要问题中需要快速判断和合并集合，就可以考虑使用并查集。

本实验中，并查集用来压缩 DFS 树中已经处理过的路径。

## 3. 为什么非树边会让树边不是桥？

因为非树边会形成环。

一旦形成环，环上的某条边被删除后，还可以绕环上的其他边到达原来的地方。

所以环上的边不是桥。

## 4. 为什么基准算法结果也重要？

因为基准算法是直接按照定义写的，虽然慢，但是逻辑最直观。

在小图和 mediumG.txt 上，可以用基准算法和高效算法互相对照，验证高效算法没有写错。

## 5. 为什么 largeG.txt 不跑基准算法？

不是因为程序不能写，而是因为它太慢。

基准算法每条边都要重新 DFS 一次。

largeG.txt 有 7586063 条边，这意味着要做 700 多万次大规模图遍历，实际运行代价太高。

# 九、给队友看的最短总结

这次实验就是找无向图中的桥。

桥的意思是：删掉这条边之后，图会断成更多块。

基准算法很直观：每次删一条边，再 DFS 看连通分支有没有变多。缺点是太慢，复杂度是 O(E*(V+E))。

高效算法的核心是：先 DFS 建树，树边暂时可能是桥；非树边会形成环，环上的树边都不是桥；用并查集把已经处理过的路径压缩掉，避免重复处理。

图 2 中有 6 条桥，两个算法都找到了 6 条，所以正确性验证通过。

mediumG.txt 中桥数量为 0，两个算法结果一致。

largeG.txt 中高效算法找到 8 条桥，运行速度很快；基准算法因为复杂度太高，没有在大图上完整运行。
